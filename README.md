# Решение
### Что было медленно 
Каждая сущность искалась `@>` по JSONB-массивам без индекса (seq scan, O(N²)) и сохранялась отдельным запросом и commit: около 400 тыс. запросов. Чистка читала всю таблицу с JSON.

### Что изменено 
Покупатели и сделки вынесены в таблицы amo_customer и amo_lead с индексами по логину и названию и ссылкой на abstract_customer. Связь сделка–покупатель идёт через общего клиента. Сопоставление по id и логину идёт по индексу в памяти, загруженному двумя запросами, а запись — одним upsert и commit на страницу CRM. Чистка — несколько DELETE по метке прогона, только после полного прохода без ошибок. Исправлены расхождения с правилами: слияние, неверный фильтр в чистке, удаление при прерванном сборе, падения на пустых полях, а в amocrm.py — потеря контактов сделок и падение на последней странице.

### Оценка 
Около 1 тыс. запросов вместо ~400 тыс., память ~30–50 МБ вместо всей таблицы. Время упирается в API CRM: 280 страниц с паузой в 1 с.
